## Data Models & Types

### Submission (Firestore Document)
```typescript
{
  id: string;              // Auto-generated by Firestore
  name: string;            // Full name
  email: string;           // Email address
  phone: string;           // Phone number
  city: string;            // City
  note: string;            // Optional note
  answers: {
    goal: string[];        // Multi-select
    level: string;         // Single select
    when: string[];        // Multi-select
    mode: string;          // Single select
    source: string;        // Single select
  };
  submittedAt: Timestamp;  // Server timestamp
}
```

### Question Object
```typescript
{
  id: string;              // Question key
  kind: 'multi' | 'single'; // Question type
  q: string;               // Question text
  sub?: string;            // Subtitle/helper text
  opts: string[];          // Answer options
}
```

## Firebase Integration Points

### Firestore Operations

**Write (OnboardingPage)**
```typescript
addDoc(collection(db, 'toastmaster-onboarding'), {
  name, phone, email, city, note,
  answers,
  submittedAt: serverTimestamp()
})
```

**Read (AdminDashboard)**
```typescript
onSnapshot(
  query(collection(db, 'toastmaster-onboarding'), 
        orderBy('submittedAt', 'desc')),
  (snapshot) => setSubmissions(...)
)
```

### Authentication

```typescript
// Listen for auth changes
onAuthStateChanged(auth, (user) => setCurrentUser(user))

// Sign out
signOut(auth)

// Protected route check
currentUser ? <AdminDashboard /> : <Navigate to="/onboarding" />
```

## Performance Considerations

1. **Code Splitting** - Components loaded on route
2. **Lazy Loading** - Routes can be lazy-loaded if needed
3. **Optimized Renders** - React.FC with proper dependencies
4. **Real-time Updates** - Firestore listeners auto-cleanup
5. **CSS Optimization** - Minimal, combined styles

## Security Architecture

```
Public Routes (/onboarding)
└── No authentication required
    └── Form data saved to Firestore
        └── Firestore security rules control access

Protected Routes (/admin)
└── Authentication required
    └── Check currentUser
    └── Redirect if not authenticated
    └── Display admin interface
    └── Firestore rules restrict admin data access
```

## Event Flow

### Onboarding Form Submission
```
User Input
    ↓
Form Validation
    ↓
onClick handler
    ↓
addDoc() to Firestore
    ↓
Handle response
    ↓
Navigate to thank you
```

### Admin Submission View
```
User navigates to /admin
    ↓
Check authentication
    ↓
Initialize Firestore listener
    ↓
Real-time updates received
    ↓
User can expand/search/filter
    ↓
Cleanup listener on unmount
```

## Error Handling

```
OnboardingPage
├── Form validation errors (display inline)
├── Firebase errors (display error message)
└── Network errors (user can retry)

AdminDashboard
├── Loading state during fetch
├── Empty state if no submissions
└── Search with client-side filtering
```
