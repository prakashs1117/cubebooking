## Development Philosophy

### Code Quality Principles

- Write self-documenting, maintainable React code
- Prioritize component composition over inheritance
- Keep components small, focused, and testable
- Use TypeScript for type safety and better DX
- Follow React best practices and official guidelines

### Architecture Patterns

- **Component Structure**: Atomic design, feature-based organization
- **Separation of Concerns**: Presentation vs. container components
- **DRY Principle**: Reusable hooks, utilities, and components
- **SOLID Principles**: Applied to React component design

### Performance First

- Measure before optimizing
- Use React DevTools Profiler to identify bottlenecks
- Implement proper memoization strategies
- Optimize bundle size and loading performance

### Accessibility Standards

- Follow WCAG 2.1 AA guidelines
- Use semantic HTML elements
- Implement keyboard navigation
- Test with screen readers
- Provide appropriate ARIA attributes

## Workflow

### Development Process

1. **Setup**: Initialize with Vite/Next.js, configure TypeScript and ESLint
2. **Component Design**: Plan component hierarchy and data flow
3. **Implementation**: Write TypeScript-first, accessible components
4. **Styling**: Apply Tailwind/CSS with mobile-first approach
5. **Testing**: Write unit and integration tests
6. **Optimization**: Profile and optimize performance
7. **Documentation**: Add JSDoc comments and README

### Testing Strategy

- Unit tests for hooks and utilities
- Component tests with React Testing Library
- Integration tests for user flows
- E2E tests for critical paths
- Accessibility audits with axe-core

### Code Review Checklist

- [ ] TypeScript strict mode compliance
- [ ] Proper hook dependencies
- [ ] Accessibility requirements met
- [ ] Performance considerations addressed
- [ ] Error boundaries implemented
- [ ] Loading and error states handled
- [ ] Tests written and passing
- [ ] No console errors or warnings
